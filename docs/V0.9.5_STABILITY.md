# Mie Survival v0.9.5 — input, frame consistency and crash prevention

v0.9.5 continues the 0.9.x stabilization cycle. It does not add progression,
biomes, mobs, structures or other content. The goal is to remove gameplay
rough edges that can still make the game feel unreliable after the v0.9.4
runtime/server stabilization.

## Release goals

1. Make keyboard, mouse and gamepad input edge-triggered and deterministic.
2. Remove camera/input spikes when gameplay resumes from menus or focus changes.
3. Prevent stale controller state after disconnect/reconnect.
4. Keep the Intel Core i5-7200U / Intel HD 620 / 8 GB RAM / HDD Low profile stable.
5. Expand regression gates before accepting further gameplay refactors.
6. Preserve v0.9.x save compatibility and multiplayer data formats unless a
   protocol change is required for a correctness fix.

## First stabilization batch

- Controller release events are emitted only on a held -> released transition.
- Controller state is cleared when no valid gamepad can be polled, preventing
  movement/buttons from remaining stuck after disconnect.
- Left and right triggers use their correct GLFW axes.
- Multiple wheel events received in one frame are accumulated rather than
  overwriting each other.
- Camera yaw uses bounded modulo wrapping instead of the previous negative-angle
  branch that could leave yaw outside the canonical range.
- Non-finite camera deltas are ignored and an invalid stored yaw/pitch is
  recovered before rebuilding the view direction.
- A fast Input and Camera Regression workflow guards these contracts in addition
  to the normal Windows and Linux builds.

## Next v0.9.5 passes

### Input and camera

- Re-synchronise mouse origin when closing inventory/map/chat so the first frame
  back in gameplay cannot rotate the camera from the UI cursor position.
- Audit focus loss/reacquisition and Alt-Tab behaviour.
- Audit dead zones and trigger normalisation for common XInput-compatible pads.
- Verify keyboard/controller parity for jump, sprint, crouch and inventory.

### Gameplay correctness

- Audit entity/player collision response, including player-to-player pushing.
- Re-run block interaction/crafting/chest/furnace invalidation paths under packet
  delay and disconnect conditions.
- Verify interaction revision handling cannot leave a client-side action stuck.
- Add targeted regression tests for any crash or soft-lock reproduced during the
  pass.

### Runtime and low-end performance

- Measure chunk bake queues during sprinting and rapid camera turns.
- Keep asynchronous work bounded when view distance changes at runtime.
- Audit allocations in frequently executed UI, entity replication and chunk
  visibility paths.
- Keep 1280x720 Low at deterministic 30 FPS as the reference acceptance target;
  performance regressions must be explained before merge.

## Release gate

v0.9.5 is ready only when:

- Windows Release CI passes;
- Linux Flatpak CI passes;
- Input and Camera Regression passes;
- Crafting UI Crash Regression remains green;
- no new save-format incompatibility is introduced;
- no known reproducible crash/blocking gameplay regression remains in the scope
  of the stabilization branch.
