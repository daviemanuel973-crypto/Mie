# Mie Survival v0.9.5 — input, frame consistency and crash prevention

v0.9.5 continues the 0.9.x stabilization cycle. It does not add progression,
biomes, mobs, structures or other content. The goal is to remove gameplay
rough edges that can still make the game feel unreliable after the v0.9.4
runtime/server stabilization.

## Release goals

1. Make keyboard, mouse and gamepad input edge-triggered and deterministic.
2. Remove camera/input spikes when gameplay resumes from menus or focus changes.
3. Prevent stale controller state after disconnect/reconnect.
4. Keep the Intel Core i5-7200U / Intel HD 620 / 8 GB RAM / HDD Low profile stable.
5. Expand regression gates before accepting further gameplay refactors.
6. Preserve v0.9.x save compatibility and multiplayer data formats unless a
   protocol change is required for a correctness fix.

## Stabilization work completed so far

### Input correctness

- Controller release events are emitted only on a held -> released transition.
- A full input reset clears pending state, typed-repeat state and edge flags, so
  focus loss cannot resurrect a key/button that was pending before the reset.
- Controller state is cleared when no valid gamepad can be polled, preventing
  movement/buttons from remaining stuck after disconnect.
- Left and right triggers use their correct GLFW axes.
- Multiple wheel events received in one frame are accumulated rather than
  overwriting each other.
- Keyboard, mouse, scroll, text and controller queries return neutral input while
  the main window is unfocused.
- Input state is now processed lazily on the first gameplay/UI query of a frame.
  The platform loop's trailing update becomes idempotent for that frame, removing
  the previous extra frame of keyboard/mouse/controller latency without advancing
  key-repeat timers twice.
- Scroll/text transient state remains available until the game/UI has consumed
  it and is cleared only at the end of the frame.

On the 30 FPS Low reference profile, removing the extra frame avoids roughly
33 ms of avoidable input latency before simulation/UI handling.

### Camera correctness

- Camera yaw uses bounded modulo wrapping instead of the previous negative-angle
  branch that could leave yaw outside the canonical range.
- Non-finite camera deltas are ignored and an invalid stored yaw/pitch is
  recovered before rebuilding the view direction.
- The resulting view direction is normalized after rebuilding rotation.

### Timing and motion robustness

- Cobweb motion rejects non-finite and non-positive frame deltas before applying
  exponential damping, preventing a single invalid delta from turning velocity
  and acceleration into NaNs.
- World-cycle construction now replaces non-finite or sub-one-second cycle
  durations with a finite one-second minimum instead of allowing invalid clock
  state to contaminate day/night progression.
- Client world-time advancement uses double precision for the intermediate phase,
  rejects non-finite totals and saturates the completed-cycle counter instead of
  converting an extreme finite frame delta through an out-of-range `uint64_t` cast.
- Survival-rule and siege/world-cycle tests cover non-finite, negative and extreme
  timing inputs.

### Siege stability

- Siege updates reject non-finite/non-positive frame deltas before warning or
  intermission timers can become NaN.
- Non-finite warning/intermission tuning is replaced with safe defaults, negative
  durations are clamped to zero, and zero wave/cycle counts are normalised to one.
- Returned spawn requests use remaining-capacity arithmetic instead of overflowing
  `unsigned int` before a clamp.
- Public enemy counts sum through `uint64_t` and clamp to the packet-visible range;
  completed-siege accounting also saturates instead of wrapping.
- Status conversion sanitises the internal timer before `ceil`/integer conversion,
  closing the NaN-to-integer path.

### Collision audit

- The existing entity/player pushing path was traced from the server chunk
  overlap query into `colideWithOthers`.
- Push candidates are already restricted to overlapping AABBs in nearby chunks
  and the current entity ID is excluded.
- No second push layer is being added without a reproducible overlap/jitter test,
  avoiding two competing collision responses for the same contact.

### Interaction invalidation audit

- The client-side prediction rollback path still contains hard assertions when an
  invalidation arrives with an empty local undo queue or a revision mismatch.
- Delayed/duplicate reliable messages can make those assumptions unsafe, so this
  is tracked as a release-blocking v0.9.5 fix rather than papered over with a
  partial helper. The eventual fix must update rollback, revision resynchronisation
  and regression coverage together.

### Regression coverage

- A fast Input and Camera Regression workflow guards input edges, focus gating,
  same-frame input consumption, scroll accumulation, controller mapping/reset and
  finite camera rotation in addition to the normal Windows and Linux builds.
- Existing survival-rules and siege-director tests now also cover invalid timing,
  saturated client world-time, malformed siege tuning and counter-overflow edges.

## Next v0.9.5 passes

### Input and camera

- Re-synchronise mouse origin when closing inventory/map/chat so the first frame
  back in gameplay cannot rotate the camera from the UI cursor position.
- Continue focus loss/reacquisition and Alt-Tab validation on packaged builds.
- Audit dead zones and trigger normalisation for common XInput-compatible pads.
- Verify keyboard/controller parity for jump, sprint, crouch and inventory.

### Gameplay correctness

- Replace assertion-based delayed/duplicate interaction invalidation handling with
  deterministic stale-message rejection and revision resynchronisation.
- Re-run block interaction/crafting/chest/furnace invalidation paths under packet
  delay and disconnect conditions.
- Verify interaction revision handling cannot leave a client-side action stuck.
- Add targeted regression tests for any crash or soft-lock reproduced during the
  pass.
- Revisit player/entity push tuning only after an overlap/jitter case is captured
  as a deterministic test.

### Runtime and low-end performance

- Measure chunk bake queues during sprinting and rapid camera turns.
- Keep asynchronous work bounded when view distance changes at runtime.
- Audit allocations in frequently executed UI, entity replication and chunk
  visibility paths.
- Keep 1280x720 Low at deterministic 30 FPS as the reference acceptance target;
  performance regressions must be explained before merge.

## Release gate

v0.9.5 is ready only when:

- Windows Release CI passes;
- Linux Flatpak CI passes;
- Input and Camera Regression passes;
- Crafting UI Crash Regression remains green;
- delayed/duplicate action invalidation no longer relies on fatal assertions;
- no new save-format incompatibility is introduced;
- no known reproducible crash/blocking gameplay regression remains in the scope
  of the stabilization branch.
