# v0.8 — Furnace Fuel and Timed Processing

This milestone replaces instant furnace crafting with a dedicated, persistent
processing block. The three interface areas are input, fuel and output; the
input area has three cells so the existing tin and bronze recipes keep all of
their v0.7 ingredients.

## Processing rules

- Copper, lead, iron, silver and gold ore retain their shipped recipe costs.
- Any supported wood log produces two charcoal.
- Tin still requires two cassiterite concentrate plus one charcoal.
- Bronze still requires three copper ingots, one tin ingot and one charcoal and
  produces four bronze ingots.
- Charcoal burns for 16 seconds, logs for 8 seconds, planks for 3 seconds and
  sticks for 1 second.
- Processing pauses without fuel or when the output is incompatible/full. A
  blocked output does not waste fuel.
- Players can remove the output but cannot insert an item into its cell.
- Breaking a furnace in Survival drops its stored input, fuel and output.

## Authority, networking and saves

The server owns recipe selection, fuel consumption, progress and output. Item
move packets are validated again against the furnace slot policy, so a modified
client cannot inject an item into the output or use an invalid fuel. Legacy
instant-furnace crafting packets are rejected; other station recipes now also
require the matching server-side interaction.

Furnace state uses a versioned block-data payload containing the five item
cells, active recipe, fuel and progress. It is included in chunk saves and block
updates. Furnaces from older worlds have no payload and automatically start as
empty v1 furnaces when first opened. Active furnaces synchronize progress at a
bounded rate rather than sending a packet every server tick.

The loader rejects truncated, oversized, trailing or non-finite state. Chunk
normalization removes orphan furnace records while preserving valid records.

## Scope

Recipe discovery/book, farming expansion, additional cooked foods and beds are
separate roadmap slices. This milestone does not change the stable v0.7.2
package or item/block numeric IDs.
