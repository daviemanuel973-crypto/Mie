# Mie Survival v0.10.1 — Low-first optimization candidate

This patch preserves the complete Low gameplay experience on the reference
i5-7200U / Intel HD 620 / 8 GB RAM / HDD system. It adds no content, removes no
mechanics, and does not lower simulation accuracy or graphical settings.

## Runtime changes

- Chunk-baking workers use the existing condition-variable wait instead of spinning
  while idle. Batch completion also waits for notification with a locked predicate;
  empty mesh queues do not wake workers or enter the completion barrier. The pool
  was extracted into a standalone unit so its actual implementation is regression-tested.

- The renderer caches back-to-front matrix indexes instead of allocating and
  sorting a vector of chunk pointers every frame. Size and relative player origin
  invalidate the cache; culling and chunk pointers are read from the current
  matrix each frame, including after unload, teleportation and distance changes.
- The mesh-baking queue sorts only its bounded 100 + worker-count prefix. All
  other dirty work remains in the existing queue for subsequent frames.
- Navigation reuses a contiguous queue bounded to 4,096 nodes per tick thread.
  At capacity, traversal stops because additional block queries cannot change
  the field. Neighbour insertion order, parents, the depth horizon, the 250 ms
  refresh rule and movement-triggered rebuilds remain the same.
- Native gameplay jobs use indexed deadlines in each priority. Future jobs are
  not scanned; execution order remains priority, deadline and ID. Cancellation,
  rescheduling, unloaded cadence and critical combat/interaction handling retain
  their contracts. Cost and deadline arithmetic saturate instead of wrapping.
- Villager society updates use deadlines, excluding unloaded profiles. Overdue
  work runs oldest first with stable ID ties under the existing 128-update budget;
  snapshot restore rebuilds the transient index. The 20/80/400-tick cadences are
  unchanged. Reads no longer expose a mutable profile that could bypass scheduling.

## Farming integrity and allocation bounds

- Region tick threads serialize cache mutations with their persistence commit,
  preventing interleaved farm saves or a second thread observing an uncommitted crop.
- Each primary and backup copy is written to a temporary file, checked for write
  errors, flushed to the OS, then replaced atomically. The primary replacement
  commits the action; a later backup failure cannot roll back acknowledged data.
- Primary and backup retain the exact format-1 payload and safeSave checksum.
  A bad primary falls back to a valid backup, including invalid semantic records.
- File sizes and exact record lengths are checked before allocation. Serialization
  reserves its final buffer once. Crop yields, growth clocks and transaction order
  relative to chunk/inventory updates are unchanged.
- Farm persistence remains a synchronous whole-registry snapshot on mutation.
  This patch does **not** claim to remove its scaling cost for very large farms;
  partitioning that storage needs a separate migration and crash-recovery design.

## Measured CPU costs

Local GCC 13.3, C++17, `-O2 -DNDEBUG`, same container/CPU for both revisions.
Seven repetitions per case; values are median microseconds per call. Scheduler
and villager baselines compile the actual v0.10.0 sources. Chunk ordering compares
the old per-frame sort with cached indexes, including index traversal. Result
checksums must match. Initialization is outside timing, except the first chunk
cache build, which is included.

| Isolated workload | v0.10.0 µs | v0.10.1 µs | Reduction |
|---|---:|---:|---:|
| 50,000 sleeping scheduled jobs | 67.1131 | 0.0061 | 99.99% |
| 2,048 due jobs, budget 64 | 229.299 | 24.0544 | 89.51% |
| 2,048 unloaded villagers | 5.6966 | 0.0040 | 99.93% |
| Chunk ordering, Low 10×10 matrix | 1.8022 | 0.0885 | 95.09% |
| Chunk ordering, 30×30 matrix | 25.5288 | 1.1776 | 95.39% |
| Chunk ordering, maximum 102×102 matrix | 911.660 | 10.5245 | 98.85% |

Navigation tests preserve every node, parent and depth from seven v0.10.0 fixtures.
For the five capacity-limited fixtures, world-block queries fall by 24–28%; flat
terrain falls from 14,420 to 10,447 queries. Completely blocked/empty fixtures keep
their original one-node result.

These are subsystem measurements, not end-to-end FPS, GPU or HDD benchmarks.
At Low, chunk ordering was already a small portion of a frame. No 30/60 FPS
guarantee or equivalent percentage increase in game FPS follows from this table.
Raw measurements: [JSON](performance/v0.10.1-microbenchmarks.json).

Reproduce on one machine:

```sh
python3 tools/benchmark_low_first.py --baseline v0.10.0 --output /tmp/mie-performance.json
```

## Compatibility and validation

- Item/block IDs, recipe indexes, saved schemas and multiplayer protocol 5 stay
  unchanged. Existing v0.9.x/v0.10.0 migrations remain in place.
- Fixed 20 Hz simulation, at most four catch-up ticks, Low defaults, 30 FPS
  foreground / 15 FPS background caps, one baking worker and no global AVX2
  requirement remain unchanged.
- New contracts compare 700 scheduler ticks to a reference implementation,
  including cancellation, priority, cadence, budgets and rescheduling; verify
  sleeping-work exclusion, arithmetic saturation, villager fairness/reload,
  cached ordering/invalidation, and seven exact navigation-field fingerprints.
- Farming regressions cover concurrent writers, competing planting attempts,
  primary failure, backup failure, reload and format-1 compatibility.
- Merge requires official Windows, Linux/Flatpak, runtime smoke and installed
  1,800-second Flatpak soak with abrupt-termination recovery. The reference
  1280×720 Low hardware session is still needed before claiming HD 620 performance.
