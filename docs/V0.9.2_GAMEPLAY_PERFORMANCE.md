# Mie Survival v0.9.2 — Gameplay & Performance

v0.9.2 is a systems release. It deliberately adds no new content and instead strengthens gameplay behavior, CPU efficiency, world-coordinate correctness and regression coverage on top of v0.9.1.

## Performance and runtime

- Replaced the pathological chunk-coordinate hash that collapsed most Z coordinates into the same buckets with a packed 64-bit hash and a SplitMix64-style finalizer.
- Replaced the pathological block-in-chunk hash with a packed XYZ key and a 32-bit avalanche finalizer.
- Fixed 64-bit region ID packing/unpacking so negative X/Z coordinates round-trip without sign extension corrupting the other axis.
- Server tick worker threads now sleep on a condition variable while idle instead of continuously polling for work.
- The server-side owner wait no longer spins at full speed while workers finish a batch; it uses a short sleep-compatible wait that also remains compatible with the existing chunk-baker workers.

## Gameplay

- Equipped item stats are now aggregated through the authoritative `getPlayerStats()` path rather than returning only the base player movement modifier.
- Player knockback resistance now participates in server-authoritative melee hit resolution.
- 100% knockback resistance cancels the impulse; positive values reduce it; supported negative resistance increases it within the existing EntityStats bounds.
- Damage, weapon damage, critical chance and existing weapon balance are otherwise unchanged by this release.

## Regression coverage

The existing Survival rules contract now verifies:

- region ID round-tripping in positive and negative coordinate quadrants;
- healthy hash distribution across a nearby 17x17 chunk area;
- knockback-resistance multipliers for neutral, resistant, immune and vulnerable cases.

## Compatibility

- No block IDs, item IDs, entity IDs, crafting recipe indexes or save schema versions are changed.
- No new packet type or multiplayer protocol field is introduced.
- v0.9.1 worlds remain the compatibility baseline.
- The v0.9.1 single-recipe crafting inventory crash fix remains intact.

## Deferred larger refactors

The audit also identified larger opportunities—pathfinding caching, per-client entity interest management, persistent chunk rebuild queues, transparency-only reordering and full sleeping synchronization for chunk baking. Those are intentionally not forced into v0.9.2 because they touch wider runtime/protocol surfaces and should be validated independently rather than increasing this release's regression risk.
