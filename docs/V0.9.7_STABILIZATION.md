# Mie Survival v0.9.7 — stabilization candidate

v0.9.7 deliberately adds no survival content. Its scope is runtime stability,
network recovery, low-end frame consistency and stronger release validation.

## Runtime and rendering

- Chunk unload removes only block-backed entities that actually exist instead
  of scanning all 65,536 block positions.
- Transparent blocks and potential decals are cached when chunk geometry changes.
  Camera movement re-sorts that sparse cache instead of rescanning the chunk.
- Chunk streaming now respects the five-packet pending limit without allowing a
  sixth packet through the boundary condition.

## Network recovery

- Client payloads have centralized size and variable-record validation before
  the server dispatches them.
- Fixed packet records are copied out of ENet buffers instead of being accessed
  through potentially unaligned C++ struct pointers.
- A pending predicted action no longer closes the game after 20 seconds. The
  client requests an authoritative inventory/block resynchronization, rolls back
  stale predictions and retries safely while keeping the session alive.
- The multiplayer protocol is version 3. v0.9.6 clients are rejected by the
  handshake rather than being allowed to exchange incompatible messages.

## Validation

- Windows build and publish workflows execute every CTest contract rather than a
  manually maintained regular expression.
- Weapon timing, interaction invalidation, crafting selection and skin format
  contracts are registered in CTest.
- The real runtime smoke runs on PRs, `main` and release tags.
- A separate 30-minute scheduled/manual soak validates a real local server,
  client, world and persistence cycle.
- The soak also kills a running session without cleanup and reopens the same
  persisted world to exercise crash recovery.
- Runtime smoke and soak runs produce JSON frame-time metrics (average, p50,
  p95, p99 and maximum) for comparable low-end measurements.

## Release gates

The candidate must not be tagged until Windows, Linux/Flatpak, runtime smoke and
all focused regressions are green. The 30-minute soak and a 1280x720 Low test on
the Intel HD 620 reference machine remain required before declaring v0.9.7 the
recommended stable build.
