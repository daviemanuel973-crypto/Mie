# v0.6 — Native systems foundation and traversal controls

Mie v0.6 turns the native-systems roadmap into executable infrastructure while
preserving v0.5 worlds, numeric content IDs and network-facing entity layouts. It
also adds configurable traversal assists and Minecraft-style camera cycling.

## Player-facing controls

- Press `F5` to cycle through first person, third person back and third person
  front.
- Open `Settings > Controls` to enable or disable automatic jumping on slabs and
  stairs, enable or disable automatic running, or cycle the camera mode.
- Automatic jump activates only while grounded, moving toward a half-height block
  and with enough head clearance. It uses a smaller impulse than a manual jump.
- Automatic run raises normal ground speed by 35%. When enabled together with
  automatic jump, approaching a clear half-height block activates both assists.
- Ladders and vines now suppress most gravity. Moving forward or holding Jump
  climbs at 5.5 blocks/second; automatic run raises that to 7 blocks/second.
- Player control preferences are local and persist in `playerControls`. Both
  assists default to disabled, while the camera defaults to first person.

The render camera and the player input camera are independent. Third-person front
therefore does not invert movement, mining, attacks or item throws. Third-person
cameras retract when a solid block is between the player and the requested camera
position, and the first-person hand is hidden while the local body is rendered.

## v0.6 foundation

### Stable content identity

The registry maps stable namespaced keys to compact runtime IDs. Every v0.5 block,
item and entity ID is frozen, while duplicate keys, duplicate IDs and persisted ID
overflow are rejected. Unknown content must use an explicit fallback.

### World schemas and migration

Each world can contain a checksum-protected `schemaManifest` safe-save payload. The
manifest currently declares the content registry, player snapshot, world progress
and prototype-machine schemas. New migrations are registered as sequential
`N -> N+1` functions and commit atomically only after every step succeeds.

Opening a v0.5 world does not rewrite chunks, players, inventories or existing
world-progress files. The v0.6 manifest and machine snapshot are independent files.

### Budgeted simulation

The server tick owns one deterministic scheduler with categories, priorities,
estimated cost and four simulation levels:

| Level | Cadence multiplier | Intended use |
|---|---:|---|
| Full | 1 | nearby active state |
| Reduced | 4 | state inside simulation distance |
| Dormant | 20 | loaded but unobserved state |
| Unloaded | 60 | discarded work until its chunk returns |

Critical combat and interaction work can pass the soft budget. Other work is
deferred deterministically. Idle prototype machines have no scheduled jobs, so
hundreds of them do not create a global per-frame update sweep.

### Dirty state, events and interest

Reusable dirty flags separate persistence, network, topology, inventory, process
and presentation changes. The internal event stream is bounded. Replication queries
declare a chunk, player, interaction, party/settlement or global interest scope;
the prototype machine currently emits only chunk-relevant deltas.

### Internal prototype machine

The authoritative prototype processor is intentionally not a player-facing block.
It validates the shared contracts before energy, pipes or other large systems are
introduced. It has bounded input/output, a deterministic 100-tick process, dirty
state, chunk-based simulation level, interest-filtered deltas, a versioned bounded
snapshot and headless metrics. The server loads it with the world, updates it from
the existing 20 Hz tick, autosaves dirty state every 30 seconds and force-saves it
during shutdown.

## Compatibility guarantees

- v0.5 block IDs `0..211`, item IDs `2048..2183` and all eight entity type IDs
  retain their meanings.
- Existing player, chunk, world-time, siege and packet layouts are unchanged.
- No v0.6 movement preference is sent to or trusted by the server as authoritative
  game state; only the resulting existing player movement data follows the current
  networking path.
- The version reported by build packaging is now `0.6.0`.

## Validation

The v0.6 test targets cover registry collision/fallback behavior, manifest
truncation, atomic migration rollback, scheduler budget/priority/cadence, dirty
flags, bounded events, interest filtering, deterministic machine processing,
snapshot restore, final-machine deletion persistence, 400 idle machines and all
movement-assist/camera setting fallbacks.

The large society, energy, logistics, fluid, mechanical, boss and dimension
systems remain outside v0.6, as defined by the execution plan.
