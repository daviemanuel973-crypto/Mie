# Mie Survival v0.9.6 release candidate

v0.9.6 is a stabilization release candidate. It deliberately avoids new survival content; the only structural addition is the requested player-skin pipeline and offline editor.

## Authoritative station interactions

Block interactions are treated as short-lived server-authoritative leases rather than trusting the position captured when the UI was opened.

- Opening a chest, furnace or crafting station validates the expected block, the player's life state and interaction reach.
- Every server tick revalidates an active station against distance, death, chunk availability and the current block identity.
- Container item movement and swaps revalidate the station before resolving container slots.
- Station-dependent crafting revalidates the required station before consuming ingredients.
- Breaking or replacing the station invalidates the open interaction.
- Rejected operations return the authoritative inventory and, when applicable, chest/furnace contents.
- Stale inventory revisions caused by lag no longer disappear silently; the server resynchronizes the client instead.

## Incremental view-distance changes

Changing view distance no longer tears down the complete client chunk cache. The client remaps chunks that remain inside the new radius, drops only chunks outside it and lets the normal server streaming loop request the newly exposed ring.

This specifically targets HDD/low-end stalls caused by `cleanup()` followed by a full chunk-system restart.

## Mie Skin v1

The renderer and multiplayer protocol keep the established 128x128 RGBA player atlas. The import layer accepts and normalizes:

- Mie Skin v1: 128x128 RGBA PNG;
- modern Minecraft skins: 64x64 PNG;
- legacy Minecraft skins: 64x32 PNG;
- legacy Mie skins: 128x64 PNG.

Minecraft-compatible UV placement is preserved. Modern 64x64 skins are scaled with nearest-neighbour sampling so pixel art remains crisp. The current player geometry remains the classic four-pixel-arm model; slim-arm geometry is intentionally deferred rather than expanding v0.9.6 scope.

`resources/tools/MieSkinEditor.html` is an offline pixel editor shipped with the project. See `docs/SKINS.md` for the format/import details.

Skin decoding is scoped only to player textures, preflights PNG dimensions before full decode and keeps the existing bounded 128x128 multiplayer payload contract.

## Release-candidate validation gates

Before v0.9.6 can be treated as a release rather than an RC, the following gates remain mandatory:

1. Windows Release CI passes and produces the portable ZIP and installer with version 0.9.6.
2. Linux Flatpak CI passes and produces the 0.9.6 bundle.
3. Skin-format and gameplay regression suites pass.
4. Release artifacts contain no personal `playerSettings` or saved worlds.
5. A real playtest covers world create/load, movement, crafting, furnace, chest interaction, combat, save/reload and abrupt termination/recovery.
6. A longer run checks memory growth, chunk queues and save stability.
7. The reference low-end machine is measured at 1280x720 Low rather than relying only on CI.

The final hardware target remains documented in `docs/LOW_END_PERFORMANCE.md`.
