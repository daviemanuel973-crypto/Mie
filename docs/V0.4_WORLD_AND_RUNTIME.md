# v0.4 — Worlds and runtime quality

This update builds on the v0.3 player persistence and safe-save format without renumbering blocks, items, entities or save fields.

## World selection

- Existing world directories are discovered safely and sorted by last played time.
- The most recent valid world is selected automatically.
- The list refreshes without scanning every frame.
- Invalid path characters, traversal names and reserved Windows device names are rejected.
- Old worlds remain valid; a lightweight `.last_played` marker is added only after a successful launch.

## Terrain and water

- Multi-block `SmallStone` structures are no longer scattered over normal forest grass.
- New chunks use the dedicated small-rock model only on rocky surfaces, river banks or hay fields.
- Water applies drag, reduced gravity and buoyancy.
- Holding Jump/Space while touching water swims upward; horizontal movement is reduced in water.

These terrain changes affect newly generated chunks only. Previously saved chunks are not silently rewritten.

## Hostile creatures

Zombies and goblins now spawn naturally on loaded, solid, dry surface terrain. Spawns are kept 18 blocks away from every player, attempted 22–46 blocks from a selected player, and capped per active player. Existing deterministic enemy variants and loot continue to apply.

> Historical note: this describes the v0.4 behavior. Starting in v0.7.2, normal
> peace-time ecology spawns pigs, cats and neutral common goblins. Zombies and
> aggressive goblins are reserved for siege waves or explicit administrator/spawn-
> egg actions.

## Windows runtime and updates

Release builds no longer allocate the development console or show profiler windows by default. `MieLauncher.exe` launches the game without a terminal, verifies official GitHub Release updates in the background, and stages them for the next launch. See [WINDOWS_UPDATES.md](WINDOWS_UPDATES.md).
