# Mie Survival v0.9.4 — gameplay and runtime stabilization

v0.9.4 deliberately adds no content. Its release gate is predictable gameplay,
bounded resource use, persistence safety and a stable Low profile on the reference
Intel Core i5-7200U, Intel HD Graphics 620, 8 GB RAM and HDD at 1280x720.

## Gameplay corrections

- Jump presses use a 100 ms input buffer and 100 ms coyote-time window.
- Collision direction bits use explicit set/clear operations, so overlapping
  collision checks cannot accidentally toggle a valid contact off.
- Block interaction walks the exact voxels crossed by a ray and checks the real
  block colliders, including secondary colliders.
- Signed block, chunk and meta-chunk conversion is exact in every quadrant and
  respects the engine's block-centred half-unit boundaries.
- Non-finite movement input and transforms are rejected or recovered before they
  can contaminate physics, chunk lookup or rendering state.
- Server combat accepts the documented `[-1, 1]` critical-chance modifier and
  rejects invalid directions or non-finite hit data.

## Server and multiplayer stability

- Simulation runs at a fixed 20 Hz with at most four catch-up ticks per host loop.
  Excess backlog is dropped rather than creating an unbounded spiral of death.
- Stale tasks from disconnected or not-yet-streamed players are discarded safely.
- AI pathfinding fields are cached per player, bounded to 4096 nodes and refreshed
  only after movement or a 250 ms interval.
- Generic entity transforms are sent at 10 Hz and only to clients that loaded the
  entity's chunk. Player movement uses the same chunk-interest filter.
- Client-controlled view distance and movement update rate are bounded server-side.
- Every handled server-to-client message has a minimum/maximum/exact-size rule.
  Decompression is limited per message and rejects unknown sizes, expansion bombs
  and malformed block-data sidecars before parsing.
- The Field Guide now uses packet header 52; header 51 remains world difficulty.
  The multiplayer handshake version is 2, so v0.9.4 clients and servers must be
  used together while the persisted player-identity format remains version 1.

## Persistence and low-end performance

- Entity sidecar temporary files are flushed to the operating system before their
  atomic rename. The existing primary/backup recovery design remains intact.
- The periodic entity-save pass skips chunks already queued for unload because the
  unload path persists them, avoiding duplicate HDD writes without weakening saves.
- Low-end Windows and Flatpak packages use deterministic 30 FPS foreground pacing
  and 15 FPS while unfocused. `MIE_FRAME_LIMIT=60` and `MIE_FRAME_LIMIT=0` are
  supported overrides.
- Low defaults remain at 1280x720, short view distance, one mesh-baking worker,
  disabled bloom/SSR/shadows/PBR and a small dynamic-light budget.

## Validation gates

- `runtime-foundation` covers signed coordinate boundaries, collision-bit
  idempotence, buffered/coyote jumping and voxel ray traversal.
- `packet-validation` covers exact, truncated, batched, unknown and decompression
  size contracts and prevents protocol-number collisions.
- Linux CI runs both new runtime contracts under AddressSanitizer and
  UndefinedBehaviorSanitizer before packaging.
- Windows Release CI builds the Low configuration without AVX2, runs all gameplay
  contracts and stages both the portable ZIP and installer inputs.
- Linux CI runs the same new contracts, validates compatibility shaders, builds the
  Flatpak repository, installs its bundle and checks writable sandboxed data paths.

Save schemas, item IDs, block IDs, entity IDs and recipe indexes are unchanged from
v0.9.3.1. Existing v0.9.x worlds remain load-compatible.
